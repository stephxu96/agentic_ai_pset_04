A CAD feature can be checked against stated rules. A simulation setup must answer the engineering question at all.\n\nReviewers need to assess loads, boundary conditions, material assumptions, contact definitions, mesh choices, solver settings, and result interpretation. A completed run is not evidence of a valid analysis.\n\nThe observed checks are narrower. Engineering.com supports reported availability. The quoted release supports what SimScale says it can do. Neither source presents a public comparison with engineer-reviewed ground truth or validation against the relevant physical system.\n\n**Visual:**\n\nA simulation result panel stamped “Run completed.” Beside it, a review gate listing: loads, boundaries, materials, contact, mesh, solver, interpretation. Caption: “What was checked: availability and a vendor-described workflow. What was not checked: correct simulation decisions.”\n\n**Source on screen:**\n\n01-c3, 01-c4 — Engineering.com, “Multiphysics gets MCP server and Onshape gets SimScale agent,” September 23, 2026.\n\n## Scene 6 — Supporting robotics context\n\n**Narration:**\n\nRobotics provides supporting context, not proof for either CAD workflow. Pilot these tools where inputs are constrained and engineering review remains explicit.\n\nFor CAD, require tests tied to intended rules and reusable parameters. For simulation, require reviewers to approve setup assumptions before treating outputs as decisions.\n\nWatch next for public task suites, disclosed graders, repeatable comparisons with engineer-authored setups, and evidence that ties a completed simulation to physical validation.
